# 规格五：自动审核与双审批

## 1. 目标

对选题和发布内容实施不可绕过的双审批，并在发布审批前完成结构化自动检查。

覆盖需求：

- `REQ-QA-001` 至 `REQ-QA-010`
- `REQ-APR-001` 至 `REQ-APR-006`
- `REQ-FEI-002` 至 `REQ-FEI-006`

## 2. 审批类型

- `topic_approval`
- `publish_approval`

选题批准只允许制作，发布批准只允许发布指定内容版本。

## 3. 自动检查

### 3.1 检查类别

| 类别 | 说明 |
|---|---|
| `fact_support` | 事实和数字是否有证据 |
| `fact_opinion_boundary` | 事实、观点、经验和推测是否混淆 |
| `freshness` | 来源是否过时 |
| `source_conflict` | 来源是否互相冲突 |
| `cross_asset_consistency` | 标题、正文和图片是否一致 |
| `privacy_secret` | 是否包含密钥、路径或个人信息 |
| `misleading_claim` | 是否夸大、误导或暗示保证结果 |
| `copyright` | 是否大段复制或过度复刻 |
| `persona_style` | 是否符合账号人格 |
| `platform_format` | 标题、图片和正文格式是否满足要求 |

### 3.2 检查结果

```json
{
  "check_type": "fact_support",
  "severity": "blocking",
  "status": "failed",
  "location": "body.paragraph_3",
  "evidence": "该数字未出现在证据包",
  "suggested_action": "删除数字或补充官方来源",
  "rule_version": "版本"
}
```

严重程度：

- `blocking`
- `warning`
- `info`

存在未解决的阻断级问题时不得创建发布审批。

### 3.3 检查执行

规则检查和模型检查分开记录：

1. 确定性检查；
2. 模型语义检查；
3. 汇总；
4. 自动修订一次；
5. 全量重新检查；
6. 仍有阻断项则转人工。

不得只重跑失败项，因为修改可能引入新的跨素材不一致。

## 4. 审批数据

### 4.1 `approval_requests`

| 字段 | 说明 |
|---|---|
| `id` | 审批请求标识 |
| `approval_type` | 选题或发布 |
| `resource_type` | 资源类型 |
| `resource_id` | 资源标识 |
| `resource_version` | 不可变版本 |
| `status` | 待处理、批准、驳回、修改、延期、失效、过期 |
| `expires_at` | 过期时间 |
| `card_message_id` | 飞书卡片标识 |
| `created_at` | 创建时间 |

### 4.2 `approval_decisions`

保存：

- 审批请求；
- 操作者；
- 操作；
- 意见；
- 操作时间；
- 飞书事件标识；
- 处理结果。

## 5. 选题审批卡片

必须展示：

- 用户问题；
- 核心结论；
- 内容支柱；
- 为什么现在值得做；
- 主要证据；
- 反例和限制；
- 实验假设；
- 首要指标；
- 评分与解释；
- 风险。

允许操作：

- 批准；
- 驳回；
- 要求补充研究；
- 提交修改意见。

## 6. 发布审批卡片

必须展示：

- 内容版本号；
- 封面预览；
- 全部图片预览或可访问附件；
- 最终标题；
- 完整正文；
- 话题；
- 来源摘要；
- 自动检查摘要；
- 警告项；
- 排期；
- 修改时间。

允许操作：

- 批准；
- 驳回；
- 要求修改；
- 延期。

## 7. 审批有效性

审批有效必须同时满足：

- 状态为批准；
- 未过期；
- 审批类型匹配；
- 账号匹配；
- 资源标识匹配；
- 资源版本匹配；
- 操作者有权限；
- 未被暂停策略阻断。

发布执行前必须重新计算有效性，不得相信排期时的缓存结果。

## 8. 版本失效

以下事件使发布审批失效：

- 标题变化；
- 正文变化；
- 图片变化；
- 话题变化；
- 来源变化；
- 风险结论变化；
- 发布账号变化；
- 内容形态变化。

排期时间在批准的允许窗口内调整不要求重新审批；超出窗口需要重新确认或延期审批。

## 9. 审批超时

- 默认有效期二十四小时；
- 超时后状态为 `expired`；
- 不自动视为驳回；
- 可基于同一未变版本创建新审批；
- 旧卡片操作返回明确过期提示。

## 10. 错误代码

| 错误码 | 处理 |
|---|---|
| `QUALITY_CHECK_BLOCKED` | 修订内容 |
| `APPROVAL_EXPIRED` | 创建新审批 |
| `APPROVAL_ALREADY_DECIDED` | 返回当前结果 |
| `APPROVAL_VERSION_MISMATCH` | 打开最新版本 |
| `APPROVER_UNAUTHORIZED` | 拒绝并审计 |
| `APPROVAL_CARD_STALE` | 更新卡片 |
| `APPROVAL_EVENT_DUPLICATE` | 幂等返回原结果 |

## 11. 验收条件

- `AC-005-01` 阻断级检查失败时无法创建发布审批。
- `AC-005-02` 自动修订最多一次，之后转人工。
- `AC-005-03` 选题批准不产生发布权限。
- `AC-005-04` 发布审批绑定不可变内容版本。
- `AC-005-05` 修改发布素材后旧审批立即失效。
- `AC-005-06` 重复点击卡片不会产生重复动作。
- `AC-005-07` 未授权用户不能审批。
- `AC-005-08` 过期卡片不能推进任务。
- `AC-005-09` 发布前可以重新验证审批有效性。

## 12. 测试重点

- 每种检查严重程度；
- 自动修订引入新问题；
- 审批和内容修改竞争；
- 卡片重复回调；
- 未授权用户；
- 审批刚过期；
- 暂停和批准同时发生；
- 延期跨出允许窗口。
