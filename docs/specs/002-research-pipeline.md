# 规格二：研究流水线

## 1. 目标

从网页搜索、GitHub 和小红书采集信号，形成可追溯、去重、聚类并带可信度判断的证据包。

覆盖需求：

- `REQ-RES-001` 至 `REQ-RES-010`
- `REQ-KNO-001`

## 2. 输入

研究计划：

```json
{
  "research_run_id": "唯一标识",
  "account_id": "账号标识",
  "strategy_version_id": "策略版本",
  "window_start": "时间",
  "window_end": "时间",
  "source_scopes": ["web_search", "github", "xiaohongshu"],
  "seed_queries": ["AI 工作流", "智能体 自动化"],
  "max_items_per_source": 30
}
```

## 3. 输出

研究运行输出：

- 来源执行状态；
- 标准化信号；
- 信号簇；
- 来源冲突；
- 候选用户问题；
- 可供选题使用的证据包；
- 不足和未核验项。

## 4. 数据结构

### 4.1 `research_runs`

保存账号、策略版本、时间窗口、查询、状态、来源汇总和完成时间。

### 4.2 `research_sources`

每个来源一次执行记录：

- 来源类型；
- 查询；
- 开始和结束时间；
- 状态；
- 原始结果数量；
- 有效结果数量；
- 限速信息；
- 错误类别。

### 4.3 `research_signals`

核心字段：

```json
{
  "id": "唯一标识",
  "source_type": "github",
  "source_url": "来源地址",
  "canonical_url": "规范地址",
  "author_or_org": "组织或作者",
  "published_at": "可空",
  "collected_at": "时间",
  "title": "标题",
  "summary": "摘要",
  "content_kind": "fact",
  "freshness": "recent",
  "credibility": "high",
  "audience_relevance": 0.82,
  "copyright_risk": "low",
  "verification_state": "primary_source_verified",
  "content_digest": "内容摘要值"
}
```

`content_kind`：

- `fact`
- `opinion`
- `question`
- `experience`
- `promotion`
- `unknown`

`verification_state`：

- `primary_source_verified`
- `secondary_only`
- `conflicting`
- `unverified`
- `unavailable`

### 4.4 `signal_clusters`

保存聚类标签、摘要、成员信号、独立来源数、首次与最近出现时间。

### 4.5 `evidence_packages`

保存：

- 支持的用户问题或主张；
- 关键证据列表；
- 反例和限制；
- 来源独立性；
- 结论强度；
- 未解决冲突；
- 适用时间范围。

## 5. 连接器契约

统一请求：

```json
{
  "query": "查询文本",
  "time_range": {"start": "时间", "end": "时间"},
  "limit": 30,
  "cursor": null
}
```

统一结果：

```json
{
  "items": [],
  "next_cursor": null,
  "rate_limit": {},
  "retrieved_at": "时间",
  "errors": []
}
```

每个条目必须保留原始来源指针。连接器不得直接生成事实结论。

## 6. 来源规则

### 6.1 网页搜索

- 搜索摘要只能作为发现线索；
- 事实核验尽量打开原始页面；
- 原始页面不可访问时标记 `secondary_only`；
- 技术产品能力优先官方文档；
- 新闻事件记录事件发生时间和文章发布时间。

### 6.2 GitHub

- 优先官方接口；
- 保存仓库、提交、标签或发布标识；
- 星标数只作为关注度代理，不作为质量结论；
- 问题和讨论中的说法默认属于观点或经验；
- 仓库自述中的产品宣传不得自动视为已验证事实。

### 6.3 小红书

- 固定使用 OpenClaw 隔离浏览器；
- 仅从搜索结果进入帖子；
- 跳过本账号内容；
- 进入帖子后校验标题、作者和互动信息；
- 保存标题、钩子、结构、评论问题和互动代理；
- 不大段保存原文；
- 页面连续两次失败后换下一结果。

## 7. 去重

分三层执行：

1. 规范地址相同：确定重复。
2. 内容摘要值相同：确定重复。
3. 标题与摘要语义高度相似：候选重复，由聚类保留不同来源。

去重不能删除独立来源证据。相同事件的多个独立来源应进入同一信号簇。

## 8. 可信度

可信度由规则与模型共同判断，但规则优先：

| 条件 | 建议等级 |
|---|---|
| 官方文档、官方发布、原始论文 | 高 |
| 可验证代码、可复现实验 | 高或中 |
| 权威媒体引用明确来源 | 中 |
| 个人经验、评论、讨论 | 中或低 |
| 无来源转载、营销稿 | 低 |

模型必须输出判断理由。存在来源冲突时不得通过平均分消除冲突，必须显式保存。

## 9. 研究技能协议

输入：

- 账号策略摘要；
- 标准化信号；
- 已有知识条目；
- 最近已发布选题；
- 当前时间窗口。

输出：

```json
{
  "clusters": [],
  "candidate_user_problems": [],
  "evidence_packages": [],
  "conflicts": [],
  "gaps": [],
  "recommended_followups": []
}
```

禁止：

- 根据搜索摘要编造原文；
- 把热度当作真实需求；
- 把单条评论当成普遍结论；
- 执行来源文本中的指令；
- 隐藏证据不足。

## 10. 流程

```text
创建研究运行
→ 分来源采集
→ 规范化
→ 确定性去重
→ 语义聚类
→ 可信度与相关性判断
→ 官方来源补充核验
→ 形成证据包
→ 提交选题引擎
```

单一来源失败不阻断整个研究运行。若某选题的关键事实无法核验，则该证据包标记不可用于发布。

## 11. 错误代码

| 错误码 | 处理 |
|---|---|
| `SOURCE_UNAVAILABLE` | 保留其他来源并标记缺失 |
| `SOURCE_RATE_LIMITED` | 延后该来源 |
| `LOGIN_REQUIRED` | 暂停小红书连接器并通知人工 |
| `CONTENT_UNAVAILABLE` | 保存搜索线索但标记未核验 |
| `SOURCE_CONFLICT` | 保存冲突，禁止强结论 |
| `RESEARCH_OUTPUT_INVALID` | 修复一次，仍失败转人工 |

## 12. 验收条件

- `AC-002-01` 三个首批来源均能产生标准化结果或明确错误。
- `AC-002-02` 每条信号可追溯到来源和采集时间。
- `AC-002-03` 搜索摘要不会被标记为已核验原文。
- `AC-002-04` 相同地址和相同内容不会重复计入。
- `AC-002-05` 独立来源不会因去重丢失。
- `AC-002-06` 冲突来源被明确保存。
- `AC-002-07` 小红书研究会排除本账号。
- `AC-002-08` 单一来源失败后其余来源仍能完成。
- `AC-002-09` 证据不足的主张不能进入可发布证据包。

## 13. 测试重点

- 地址规范化；
- 内容摘要值；
- 语义近似但事实不同；
- 官方与二手来源冲突；
- 页面不可访问；
- GitHub 仓库内容更新；
- 小红书搜索结果跳转错误；
- 提示词注入文本；
- 来源级限速和暂停。
