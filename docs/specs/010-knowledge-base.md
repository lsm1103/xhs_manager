# 规格十：用户问题库与运营知识库

## 1. 目标

将评论中的真实问题和运营过程中的可复用经验沉淀为可检索、可追踪、具有生命周期的知识。

覆盖需求：

- `REQ-INS-001` 至 `REQ-INS-006`
- `REQ-KNO-001` 至 `REQ-KNO-008`

## 2. 两类存储

### 2.1 用户问题库

回答：

- 用户试图完成什么任务；
- 在什么场景；
- 遇到什么限制；
- 已经尝试什么；
- 哪些问题反复出现。

### 2.2 运营知识库

回答：

- 过去怎么做；
- 什么有证据支持；
- 什么失败；
- 什么可以复用；
- 下次应该如何调整。

问题库不等于商业需求库，知识库不等于流水日志。

## 3. 问题候选

`problem_candidates` 字段：

- 标识；
- 脱敏来源评论；
- 帖子；
- 用户任务；
- 场景；
- 限制；
- 已尝试方法；
- 结果；
- 分类置信度；
- 创建时间；
- 人工确认状态。

禁止保存不必要的手机号、邮箱、微信号和完整用户身份信息。

## 4. 问题聚类

`problem_clusters` 字段：

- 标识；
- 标准问题描述；
- 适用用户阶段；
- 独立用户数量；
- 候选数量；
- 首次和最近出现时间；
- 代表性脱敏证据；
- 状态；
- 是否进入选题池；
- 是否建议进一步访谈。

聚类合并必须保留旧簇映射，不能删除来源。

## 5. 知识条目

类型：

- `account`
- `topic`
- `pattern`
- `action`
- `review`

结构：

```json
{
  "knowledge_entry_id": "唯一标识",
  "type": "pattern",
  "status": "experimental",
  "summary": "一句话结论",
  "evidence_refs": [],
  "reusable_rule": "适用条件和用法",
  "risks": [],
  "next_action": "下一步",
  "confidence": "medium",
  "valid_from": "时间",
  "valid_until": null,
  "supersedes_id": null
}
```

状态：

- `experimental`
- `active`
- `deprecated`

## 6. 写入时机

- 研究后：选题和来源规律；
- 发布后：动作记录；
- 评论后：问题候选；
- 单篇复盘后：实验知识候选；
- 周复盘后：模式候选；
- 人工确认后：升级为生效；
- 失效后：标记废弃并说明原因。

## 7. 升级规则

模型只能创建 `experimental` 候选。

升级为 `active` 必须：

- 有明确证据；
- 有适用条件；
- 不与现有生效知识冲突，或已解释冲突；
- 运营者确认。

降级为 `deprecated` 必须保存：

- 失效原因；
- 失效证据；
- 替代条目；
- 操作者和时间。

## 8. 检索

检索顺序：

1. 当前生效账号策略；
2. 最近十四天同类记录；
3. 同账号、同主题；
4. 同结构模式；
5. 历史失败。

返回：

- 匹配数量；
- 最相关三条；
- 可复用点；
- 风险；
- 当前任务建议。

检索结果必须包含知识状态和证据指针，废弃知识不得作为默认建议。

## 9. 文件与飞书投影

SQLite 保存结构化权威记录。

本地可生成便于人和智能体阅读的文件投影：

```text
knowledge-base/
  README.md
  accounts/
  topics/
  patterns/
  actions/
  reviews/
```

飞书文档保存周期摘要和链接。

文件或飞书投影失败不改变数据库知识状态，可通过补偿任务重建。

## 10. 隐私

- 作者身份使用脱敏标识；
- 原评论仅保存必要片段；
- 联系方式默认删除；
- 用户要求删除相关信息时支持按来源定位；
- 飞书文档不展示未经必要处理的个人信息。

## 11. 错误代码

| 错误码 | 处理 |
|---|---|
| `PROBLEM_DATA_INSUFFICIENT` | 保留候选，不聚类 |
| `PROBLEM_PRIVACY_BLOCKED` | 脱敏后重试 |
| `KNOWLEDGE_CONFLICT` | 人工判断 |
| `KNOWLEDGE_EVIDENCE_MISSING` | 不得升级 |
| `KNOWLEDGE_STATUS_INVALID` | 拒绝 |
| `KNOWLEDGE_PROJECTION_FAILED` | 补偿重建 |

## 12. 验收条件

- `AC-010-01` 有效评论能形成脱敏问题候选。
- `AC-010-02` 聚类保留独立用户数量和来源。
- `AC-010-03` 高频问题不会自动变成商业需求。
- `AC-010-04` 模型不能直接创建生效知识。
- `AC-010-05` 生效知识具有证据和适用条件。
- `AC-010-06` 废弃知识保留历史和原因。
- `AC-010-07` 文件或飞书投影可从数据库重建。
- `AC-010-08` 检索默认排除废弃知识。

## 13. 测试重点

- 联系方式脱敏；
- 同一用户多条评论；
- 不同用户相同问题；
- 相似但约束不同的问题；
- 知识冲突；
- 旧知识废弃；
- 投影写入失败；
- 来源评论删除。
