# 工具选型、接入边界与阶段路线

## 1. 文档目的

本文件记录已经调研的外部工具、它们在本项目中的准入结论、凭证类型、使用环节和接入顺序。

根本原则是：工具提供可替换的能力，项目自身负责状态机、审批、幂等、审计、密钥和发布决策。任何 Skill、CLI、浏览器自动化或图片服务都不得直接修改业务表、绕过审批或执行未经工作流授权的发布动作。

本文件的事实依据来自以下一手仓库：

- [Agent Reach](https://github.com/Panniantong/Agent-Reach)
- [OpenCLI](https://github.com/jackwener/opencli)
- [xhs-writer-skill](https://github.com/JuneYaooo/xhs-writer-skill)
- [guizang-social-card-skill](https://github.com/op7418/guizang-social-card-skill)
- [Humanizer-zh](https://github.com/op7418/Humanizer-zh)
- [baoyu-skills](https://github.com/JimLiu/baoyu-skills)
- [Kami](https://github.com/tw93/kami)
- [HyperFrames](https://github.com/heygen-com/hyperframes)
- [web-access](https://github.com/eze-is/web-access)
- [魔因漫创 Moyin Creator](https://github.com/MemeCalculate/moyin-creator)
- [ChatCut Agent Plugin](https://github.com/ChatCut-Inc/agent-plugin)
- [Flova AI](https://www.flova.ai/zh-CN/)

## 2. 阶段定义

| 阶段 | 范围 | 当前结论 |
|---|---|---|
| 当前阶段：可靠性骨架与研究数据底座 | SQLite、工作项、审批、暂停、审计、研究运行/信号/证据包和真实外部动作硬关闭 | 已完成；研究仅有内部契约接口，不安装会产生真实外部副作用的工具 |
| 下一阶段：研究、选题和内容制作 | 飞书自建应用、研究连接器、证据包、模型网关、内容版本、图片和自动检查 | 优先接入只读研究、结构化内容和图片生产能力 |
| 后续阶段：发布、评论和复盘 | 小红书发布适配器、评论运营、指标、知识库和复盘 | 只在演练通过后开启浏览器写操作；报告与知识沉淀随后接入 |
| 未来阶段：短视频 | 视频脚本、动画、渲染、审核和视频发布 | 图文闭环稳定后再评估，不进入当前开发范围 |

## 3. 总体接入拓扑

```text
研究源与真实素材
  ├─ Agent Reach / OpenCLI（只读研究）
  ├─ 网页、GitHub、小红书
  └─ 证据包与来源记录
          ↓
选题审批
          ↓
内容生成适配器
  ├─ 项目模型网关
  ├─ xhs-writer-skill（候选内容包）
  └─ Humanizer-zh（可选风格编辑）
          ↓
视觉生产适配器
  ├─ guizang-social-card（最终 HTML 卡片）
  ├─ baoyu-diagram（SVG 技术图解）
  └─ GPT Image 2（背景、插图、图生图）
          ↓
自动检查与发布审批
          ↓
OpenClaw 隔离浏览器发布适配器
          ↓
指标、复盘、知识库与 Kami 报告
```

## 4. 工具决策总表

| 工具 | 阶段 | 项目定位 | 凭证或运行前提 | 准入结论 |
|---|---|---|---|---|
| Agent Reach | 下一阶段 | 网页、GitHub、小红书等研究源路由与诊断 | 基础网页和公开源通常无需 Key；小红书等需登录态或 Cookie | 接入研究连接器；只读 |
| OpenCLI | 下一阶段、本地开发 | 桌面 Chrome 登录态研究与网页契约调试 | Node.js 20+、浏览器扩展、独立 Chrome Profile、登录态 | 仅本地研究和调试；不作为服务器生产发布器 |
| xhs-writer-skill | 下一阶段 | 内容初稿、标题候选、素材分析、卡片方案 | 图生图需要 OpenAI API Key；纯文字卡片可不使用 Key | 以适配器方式试点；不直接控制工作流 |
| guizang-social-card | 下一阶段 | 小红书 3:4 图文卡的最终排版、渲染与版式检查 | Node.js、Playwright；外部取图可能需要网络访问 | 优先采用；作为图片制作主方案 |
| baoyu-diagram | 下一阶段 | 技术科普中的 SVG 流程、架构和时序图 | 无图像 API Key；需要 Agent 生成 SVG | 选择性采用；作为图解组件 |
| baoyu-image-gen | 下一阶段，可选 | 多图片供应商的统一调用命令 | 所选供应商的 API Key | 不直接依赖；项目图片网关需要多供应商时再采用 |
| Humanizer-zh | 下一阶段，可选 | 文案去模板化和语气编辑 | 使用项目既有模型能力 | 允许作为二次编辑；每次改写后重新全量检查 |
| Kami | 后续阶段 | 研究报告、周复盘、归档文档和飞书展示 | Node.js 与文档渲染依赖 | 后置接入；不用于小红书卡片 |
| web-access | 下一阶段，备用 | 动态网页和浏览器研究的备用通道 | Node.js 22+、本地 Chrome、登录态 | 不进入生产；与 OpenCLI 二选一做本地备用 |
| Jacky-OPC | 暂不接入 | 内容流程和发布前规则参考 | 来源、依赖和凭证尚未完成一手审计 | 仅参考规则，不安装、不调用 |
| HyperFrames | 未来阶段 | HTML 到 MP4 的确定性产品介绍、技术演示和动效视频渲染 | Node.js 22+、FFmpeg；云端渲染另需 AWS 凭证 | 视频阶段优先评估；暂不接入图文主链路 |
| ChatCut | 未来阶段 | 口播素材粗剪、字幕、音频清理、转场、动效和导出 | ChatCut 账户、OAuth 授权、项目访问权限；AI 功能按积分计费 | 口播和已有素材优先试点；不把托管项目状态作为权威业务状态 |
| 魔因漫创 Moyin Creator | 未来阶段，专题内容 | 剧本、角色、场景、分镜到批量生成视频的短剧生产 | Node.js 18+；所选图像和视频供应商 API Key；AGPL-3.0 或商业许可证 | 暂不接入；仅在动漫短剧或预告片专题立项后进行许可证与安全审计 |
| Flova AI | 未来阶段，探索 | 托管式视频 Agent、资产库、角色和场景连续性管理 | Flova 账户与平台积分；视频、图像、音乐、旁白和编辑均消耗积分 | 仅作为探索性 SaaS 备选；先进行成本和数据授权试验 |

## 5. 凭证与会话分类

| 类别 | 示例 | 存放与使用规则 |
|---|---|---|
| 模型 API Key | OpenAI GPT Image 2、其他图片供应商 | 只由环境变量或密钥服务注入；不写入 Skill 目录、业务表、日志、飞书正文或提示词 |
| 平台应用凭证 | 飞书应用凭证、未来正式平台 API Token | 只由连接器读取；轮换要可审计 |
| 浏览器登录态或 Cookie | 小红书、GitHub、OpenCLI、web-access | 等同高权限凭证；必须使用隔离 Profile；不导出到业务数据库和日志 |
| 本地运行依赖 | Node.js、Playwright、Chrome 扩展、FFmpeg | 健康检查记录版本与可用性；不得把缺失依赖伪装成业务失败 |

## 6. 下一阶段的工具使用步骤

### 6.1 研究：Agent Reach 与 OpenCLI

1. 调度器创建研究运行，绑定账号策略版本、查询和时间窗口。当前项目已实现该记录、来源执行记录、标准化信号、URL/内容摘要去重和证据包审阅接口。
2. 研究连接器先执行网页和 GitHub 等无需登录的来源。
3. 小红书研究只在独立浏览器 Profile 已由运营者手动登录后执行。
4. Agent Reach 负责选择或诊断可用后端；OpenCLI 仅在本地开发机用于读取 DOM、验证页面流程或采集研究结果。
5. 连接器返回标准化信号，而不是自由文本：来源地址、采集时间、标题、摘要、互动信号、原始证据位置和失败类型。
6. 项目完成去重、可信度标记、聚类和证据包生成；当前最小实现已完成前两层去重和证据包，聚类及真实连接器仍待接入。模型只消费脱敏后的必要数据。
7. 研究失败最多自动重试一次；登录失效、平台风控或结果不完整转人工。

禁止事项：OpenCLI 和 Agent Reach 不得点击小红书最终发布按钮，不得读取日常 Chrome Profile，不得把 Cookie 传给模型。

### 6.2 选题与初稿：xhs-writer-skill

1. 仅处理已创建的内容任务，并读取已批准或待审批的证据包、账号策略投影和素材清单。
2. 生成三至五个标题候选、正文初稿、标签候选和卡片结构；输出必须带来源引用标识与内容版本草稿标识。
3. 有真实截图或授权素材时，优先使用图生图；没有素材时只生成视觉脚本或纯文字卡片，不虚构产品实拍。
4. 如启用 GPT Image 2，图片网关从环境变量读取 Key，并记录模型名、请求摘要、成本和输出文件校验值，不记录 Key。
5. 内容版本进入确定性检查：事实支持、版权、敏感表达、账号人格、格式和素材一致性。
6. 任何自动修订最多一次；修改后必须重新运行全部检查；阻断项未消除则进入人工修改。
7. 最终预览只由项目创建飞书发布审批，Skill 不得直接发布。

### 6.3 图片：guizang-social-card、baoyu-diagram 与图片网关

1. 内容服务先生成视觉脚本：每页目的、关键结论、文本预算、图表类型、授权素材和来源。
2. 技术流程、架构和时序关系优先由 `baoyu-diagram` 生成 SVG，作为可校验、可复用组件。
3. 背景、插图或真实素材风格统一需要时，通过项目图片网关调用 GPT Image 2；对图生图明确保留哪些事实性界面和文字。
4. `guizang-social-card` 将文字、SVG、图片和来源信息组合为 1080×1440 的 HTML 卡片，并使用 Playwright 渲染 PNG。
5. 运行版式校验：溢出、字号、页脚碰撞、内容密度和标题间距。
6. 产物保存为不可变图片版本：HTML 源、PNG、SVG、素材来源、渲染参数、校验结果和文件摘要。
7. 审批卡展示完整图片组；任意图片、标题、正文、标签或来源改变都会使旧审批失效。

### 6.4 文案风格：Humanizer-zh

1. 只在事实、版权和敏感表达检查通过的正文草稿上运行。
2. 输入必须声明目标受众、账号人格、不可改动事实和引用标识。
3. 输出为改写建议或新草稿版本，不覆盖原稿。
4. 改写后重新运行事实支持、敏感表达、平台格式和人格检查。
5. 不以“规避 AI 检测”为目标；不接受任何保证检测结果的声明。

### 6.5 审批后发布：OpenClaw 浏览器适配器

1. 发布器只读取已排期、审批有效且内容版本完整的发布计划。
2. 使用服务器中的隔离 `openclaw` Profile；运营者手动维持登录，不自动输入账号密码。
3. 打开图文编辑页、上传已归档素材、填写标题正文与话题，并保存发布前证据。
4. 最终点击前重新验证暂停状态、审批有效性、内容版本、账号身份和幂等外部动作。
5. 只点击一次；任何网络中断、页面异常或系统崩溃后都标记为结果未知，先核验再决定是否重试。
6. OpenCLI、web-access、xhs-writer-skill 与 guizang-social-card 均不得替代本步骤。

## 7. 后续阶段的工具使用步骤

### 7.1 报告、复盘与知识沉淀：Kami

1. 指标服务生成单篇和周复盘的结构化数据，不直接让模型凭印象写结论。
2. 复盘模型只形成假设、证据、反例、风险和建议动作；不得自动修改账号策略。
3. Kami 将已批准的结构化报告渲染为飞书可展示的文档或导出文件。
4. 归档记录保存报告版本、关联内容任务、数据窗口和策略版本。

### 7.2 视频：工具分工与准入

视频能力不属于当前最小可行产品。只有在连续运行图文闭环、验证选题方向并明确视频验收指标后，才建立独立的视频规格。视频项目必须独立于图文内容任务，拥有自己的脚本版本、素材授权、渲染作业、人工审批和发布记录。

| 内容类型 | 首选工具 | 选择原因 | 不适用边界 |
|---|---|---|---|
| 技术评测、产品介绍、网页或代码演示 | HyperFrames | HTML/CSS 可审计、可复现，适合图表、字幕、屏幕录制和动效 | 不擅长角色连续叙事和真人口播原素材粗剪 |
| 口播、访谈、录屏和现成素材剪辑 | ChatCut | 可导入素材、转录、加字幕、清理音频、调整时间线、生成动效并导出 | 成本和项目状态依赖托管服务；不得把账号授权交给模型 |
| 动漫短剧、连续角色故事、预告片 | 魔因漫创 | 剧本解析、角色圣经、场景、分镜与多镜头视频生成是一体化流程 | AGPL-3.0 对闭源集成有约束；需要多个模型供应商 Key；不适合当前技术科普主线 |
| 长期连续角色或场景的生成式剧集探索 | Flova AI | 提供资产库、技能和视频 Agent 形态，面向连续创作 | 托管积分模式，成本和生成权利需先按实际合同与平台条款确认 |

所有视频工具共用以下步骤：

1. 运营者批准视频选题，明确目标受众、时长、内容形式、首要指标和预算上限。
2. 系统生成脚本、事实来源和视觉分镜；涉及事实的字幕、旁白和图表必须回链到证据包。
3. 素材服务核验自有、授权、开源许可或可商用生成素材，不得把未知来源的影视、音乐或角色资产直接投入生成。
4. 按内容类型选择一个主工具；同一视频版本不得在多个工具中无记录地混剪。
5. 每次生成或编辑创建渲染作业，记录输入素材摘要、工具版本、模型/供应商、积分或成本、输出校验值和失败原因。
6. 自动检查时长、分辨率、字幕完整性、音频峰值、敏感表达、版权来源和品牌一致性。
7. 飞书展示低码率预览、脚本、素材来源、成本汇总和最终导出文件，等待人工视频审批。
8. 审批通过后才调用独立的视频发布适配器；发布结果未知时先核验，不重复提交。

各工具专用步骤：

- HyperFrames：已批准分镜 → HTML 合成与可定位动画 → 本地预览和渲染 → MP4 质量检查。基础本地渲染不需要模型 Key，但运行环境需要 Node.js 22+ 和 FFmpeg。
- ChatCut：运营者先创建或授权一个 ChatCut 项目 → 通过 OAuth 登录插件 → 导入口播、录屏或素材 → 自动转录、粗剪、字幕和动效建议 → 人工检查时间线 → 导出。插件连接的是托管 MCP 服务，需要 ChatCut 账户和项目访问权限；AI 编辑和生成功能消耗平台积分。
- 魔因漫创：已批准剧本 → 解析场景、角色和对白 → 建立角色圣经与场景资产 → 生成和人工修订分镜 → 按模型约束批量生图、生视频 → 组片与质量检查。它要求配置所选 AI 服务商 API Key；若项目采用闭源集成，必须先取得商业许可证。
- Flova AI：先建立项目和资产库 → 固化角色、场景、风格与提示词规则 → 按镜头生成、衔接和复核 → 下载导出文件并保存到项目素材库。它使用账户积分而非本项目托管 Key；使用前需记录订阅、单镜头成本、导出权利和数据处理条款。

## 8. 实施顺序与验收门槛

| 顺序 | 交付项 | 工具 | 最小验收门槛 |
|---:|---|---|---|
| 1 | 研究数据底座（已实现）与研究连接器 | 内部契约接口；后续 Agent Reach、本地 OpenCLI 调试 | 已能保存来源执行、标准化信号、去重关系和证据包；真实网页、GitHub、小红书连接器仍需满足登录失效不自动登录 |
| 2 | 结构化模型网关与内容版本 | xhs-writer-skill | 模型不能写业务表；所有输出可追溯到策略和证据包 |
| 3 | SVG 与图片生产 | baoyu-diagram、GPT Image 2、guizang-social-card | 3:4 图片组可渲染、可校验、可追溯且不含未授权素材 |
| 4 | 内容检查与审批 | Humanizer-zh（可选） | 改写后全量复检；阻断项不能创建发布审批 |
| 5 | 发布演练与真实发布 | OpenClaw 浏览器适配器 | 重复触发只形成一次发布；结果未知不重发 |
| 6 | 复盘和知识库 | Kami | 报告绑定数据窗口和策略版本；建议不能自动生效 |
| 7 | 视频规格与小样 | HyperFrames、ChatCut、魔因漫创或 Flova AI | 单独定义视频规格、成本、授权、审批和发布验收条件；一次只试验一种主工具 |

## 9. 维护规则

- 新工具进入项目之前，先补充本文件中的来源、许可证、功能、凭证、运行依赖、允许动作和替代方案。
- 工具升级、模型切换、凭证类型变化或浏览器自动化行为变化时，更新本文件并执行对应连接器契约测试。
- 生产只部署已经通过本项目连接器契约测试的工具版本；开发机中的 Skill 安装不等于生产准入。
- 工具失效时先切换适配器或降级为人工处理，不修改领域状态机和审批规则。
