# AI 技术科普小红书自动运营系统

本仓库已完成产品定义、技术顶层设计、开发规格和第一阶段可靠性骨架。

## 运行

```bash
./run.sh
```

一条命令拉起两个进程，Ctrl-C 一起停：

| 进程 | 干什么 |
|---|---|
| 主服务 | API（`/v1/*`）、控制台（`/console`）、配音（`/tts/*`），默认 `127.0.0.1:8000` |
| worker | 从 `work_items` 队列领视频阶段来跑（采集 / 脚本 / 素材 / 组合 / 渲染） |

只起一个：`./run.sh api` 或 `./run.sh worker`。
换端口：`XHS_PORT=8001 ./run.sh`。
跳过启动时的数据库迁移：`./run.sh --no-migrate`。

控制台在 http://127.0.0.1:8000/console —— 任务台、采集、资产、配音、运行、工具六页，
发布审批和阶段重跑也在这里。

> **别用 `kill -9` 停主服务。** 配音的重模型（IndexTTS-2、OmniVoice）是它的子进程，
> 靠退出钩子卸载；硬杀会留下几个 GB 的孤儿进程。Ctrl-C 或 `kill` 都会走优雅退出。

跑一次性的任务不需要 worker：

```bash
.venv/bin/python -m xhs_manager.video_pipeline.cli --help
```

## 发布：默认不自动发

小红书默认走**人工发布**（`XHS_VIDEO_XHS_PUBLISH_MODE=manual`）：
流水线把标题、正文、标签、成片都备好，在控制台任务详情页列成一张清单，
每项一个复制按钮，你自己粘到小红书里发。发完点「我已发布」记一笔。

这一步一行浏览器代码都不碰。另外两种模式会驱动 Chrome 登录你的真实账号操作：

| 模式 | 行为 | 风险 |
|---|---|---|
| `manual`（默认） | 只在控制台列出要填的内容 | 无 |
| `draft` | 浏览器自动化登录，存成草稿 | 自动化操作真实账号 |
| `publish` | 浏览器自动化登录，直接发出去 | 自动化操作真实账号 |

`draft` 和 `publish` 这类自动化已经导致过一次封号。要用得自己明确改配置。

## 当前产品基线

- 新建 AI 技术科普小红书账号；
- 目标用户是希望从对话式 AI 进阶到可运行工作流的人；
- 账号人格是“AI 工作流实验员”；
- 每周五篇图文；
- 研究、制图、排期、审批后发布、低风险评论回复、统计和归档自动执行；
- 选题和发布前必须人工审批；
- 飞书是控制入口，SQLite 是权威状态源；
- 首批研究源是网页搜索、GitHub 和小红书；
- 第一阶段验证涨粉、内容方向和用户问题，不销售明确产品。

## 已实现

- SQLite 与 Alembic 迁移；
- 内容任务状态机；
- 持久工作项和租约；
- 命令及外部动作幂等；
- 选题和发布双审批领域服务；
- 飞书标准化回调、白名单和重复事件处理；
- 自动化暂停、审计和健康检查；
- 研究运行、来源执行、标准化信号、确定性去重和证据包的内部审阅接口；
- 已接入经审批后的小红书草稿准备执行器；公开发布与评论仍保留人工确认边界。

## 后续开发顺序

1. 飞书企业自建应用适配器；
2. 可替换的只读研究连接器与研究确认后的选题引擎；
3. 内容与图片；
4. 小红书发布；
5. 评论；
6. 数据、复盘与知识库；
7. 端到端故障演练。

实现时每个开发任务都应引用对应规格中的验收条件。
